How I test

Working principles

Break it before the user does

Principle

A methodical, investigative mindset built through structured test case design, edge-case testing, and regression testing across web and mobile (Android & iOS) to ensure no bug escapes to production.

Bugs need business context

Principle

A defect report is only useful if the reader understands the impact. I write bugs that make sense to engineers and to non-technical stakeholders alike.

Automate the repeatable stuff

Principle

Manual exploration finds what automation can't predict; automation protects what manual testing already proved.

Data doesn't lie, headlines do

Principle

Digging past the top-line number is the same instinct whether I'm testing edge cases or analysing a dataset — the real story is usually one layer down.

Prioritise over perfection

Principle

Full test coverage isn't realistically possible on most projects. What matters is prioritising by risk and impact, then fixing as many issues as possible within the time available.

Working software isn't enough

Principle

Fixing every bug doesn't help if the software is still hard to use or doesn't meet user needs. Testing has to check requirements are met and the experience actually works for users, not just that defects are gone.
